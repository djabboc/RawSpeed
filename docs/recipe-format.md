# 编辑配方格式与迁移

编辑配方保存在原片旁的 `<照片文件名>.rawspeed.json`。应用只在用户保存时写入边车，先校验内容，再以临时文件原子替换。照片本身保持只读。

## 版本 2

`Version` 为 `2`，`Settings` 和 `LutStrength` 的含义与版本 1 相同。目录滤镜新增可空的 `LutSource`，记录稳定的目录 `Id`、显示名称 `Name`、种类 `Kind`、原文件绝对路径 `OriginalPath`、原文件内容 `SourceSha256` 和适配器 `AdapterVersion`。普通 sRGB Cube 的适配版本为 `null`；电影和社区预设使用当前 `rawspeed-display-v1`。

使用 `LutSource` 时，`LutPath` 必须为 `null`。临时生成的 Cube 位置只属于缓存，不进入新配方。应用从同一份源字节计算身份和生成颜色转换，避免源文件在两次读取间发生变化。

重新打开照片时，先按目录 ID 在当前安装中寻找原预设，再尝试记录的原始路径。仅接受 SHA-256 相同的原文件，并使用配方记录的适配算法；缓存缺失或损坏时重新生成。这允许安装目录和缓存目录移动，同时保持保存的外观。未来适配算法升级必须保留旧实现，或明确报告旧版本不可用，不能无提示地用新算法替换。

原文件缺失、内容改变或适配版本不可用时，应用显示提示和“暂不可用”，保留已保存的滤镜身份与强度。预览暂时只显示其他编辑；为避免输出缺少保存效果的文件，导出暂停。保存其他调整仍保留该引用。恢复原文件后重新打开照片可以恢复效果；明确清除滤镜、切换内置预设或重置会移除引用，并支持撤销/重做。

## 版本 1 兼容

读取版本 1 后只在内存中升级到版本 2，不自动重写用户边车，也不改变编辑参数。普通用户导入 Cube 的 `LutPath` 继续有效。

对于历史生成缓存路径，应用识别文件名中的适配器版本、滤镜种类和源 SHA-256，与当前电影/社区目录中的原文件匹配。匹配后可重建已经删除的缓存，并在下一次保存时改为稳定的 `LutSource`。此转换不产生虚假的“未保存编辑”状态。

旧缓存无法匹配原预设但文件仍存在时，继续使用原路径；原缓存和原预设都缺失时保留路径并提示，不将滤镜静默清空。版本 1 无法凭空恢复缺失文件中的颜色数据。

不支持的配方版本、非法引用、非法参数或超过 1 MiB 的边车均拒绝加载。源引用和旧路径不能同时存在。测试使用自行生成的照片、Cube 和社区 JSON，覆盖关闭应用、删除缓存、迁移安装目录、旧格式恢复、缺源/源变更以及清除/撤销/重做。
