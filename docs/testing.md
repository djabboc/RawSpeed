# 测试与复现

本页区分像素/文件流程、应用状态、WPF 组件和真实桌面验证。完整文件流程已通过；真实桌面鼠标、文件对话框提交和高 DPI 验收尚未全部完成，不能把组件渲染图当成桌面截图。

## 运行方式

在仓库根目录、安装 .NET 9 SDK 的 Windows x64 环境运行：

```powershell
dotnet run --project tests/RawSpeed.Core.Tests -c Release
dotnet run --project tests/RawSpeed.App.Tests -c Release
dotnet run --project tests/RawSpeed.IntegrationTests -c Release
dotnet run --project tools/RawSpeed.UiProbe -c Release
```

可选核心性能测量：

```powershell
dotnet run --project tests/RawSpeed.Core.Tests -c Release -- --benchmark
```

集成测试需要以下本地样张：`example/nikon.NEF`、`example/olympus.ORF`、`example/P1010002.JPG`。样张未纳入 Git；克隆仓库后需要自行准备具有再使用权限的样本。可以将仓库根目录作为集成程序的第一个参数传入。测试进程返回 `0` 表示成功，`1` 表示验证失败，`2` 表示参数或仓库目录错误。

所有导出写入唯一的 `artifacts/integration-runs/<时间-GUID>/` 目录，包含用于验证的 `.cube` 文件、三张照片的编辑后 JPEG/PNG 和无效输入夹具。原照片不会被覆盖。汇总报告写入 `artifacts/integration-results.json`，并在每次输出目录保存 `results.json`，包含每项检查、图像尺寸、解码模式、源文件前后 SHA-256、元数据目录、JPEG 像素误差、各阶段耗时和运行环境。汇总报告是最近一次执行的结果，历史输出目录保留。

## 覆盖范围

三个用户样张分别完成以下流程：

1. 对 RAW 提取内嵌预览，并验证它被明确标记为内嵌 JPEG；随后走真正的 LibRaw 显影预览。JPEG 的内嵌 RAW 预览接口应返回空。
2. 验证 1600px 长边限制、RGBA 缓冲尺寸、透明度和非空图像；读取全部元数据，确认相机型号、Nikon/Olympus MakerNotes，以及 NEF 的实际 XMP 属性。
3. 独立应用曝光、白平衡、曲线、色相/饱和度、降噪和拉直，确认真实样张产生变化。导入磁盘上的 17³ `.cube`，验证风格生效。
4. 组合曝光、白平衡、曲线、色彩、LUT、降噪、90°旋转、拉直、翻转与裁切；确认输出尺寸、RGB 直方图计数和输入像素未被修改。
5. 从原文件重新进行完整分辨率解码，以相同参数处理并导出 JPEG/PNG。JPEG 再经应用文件服务打开；PNG 由底层图像库独立打开。检查尺寸和颜色声明、PNG 逐字节无损回环、JPEG 平均绝对 RGB 误差小于 15/255。
6. 比较原文件 SHA-256，确认全流程没有修改原片。

另外五组检查覆盖：损坏的 JPG/NEF/ORF、缺失与不支持文件、预先取消的解码/渲染/导出、RAW 调用开始后的取消及后续解码恢复、现存输出文件保护与同时导出到同一路径的竞争。并发导出必须仅一个成功，失败操作不能留下临时文件。

PNG 的颜色声明既可以是 ICC profile，也可以是标准 `sRGB` chunk。ImageMagick 会将标准 sRGB profile 简化为 `sRGB`/`gAMA` chunks；测试按 PNG 规范接受此形式，不能把 `GetColorProfile() == null` 单独当成颜色信息丢失。

核心测试另外验证确定性的像素数学行为：旋转/翻转/裁切位置、LUT 插值与输入范围、曲线与预览一致性、噪声方差下降与边缘保持、取消和多线程确定性。集成测试主要验证跨模块连接和真实文件行为。

## 性能测量口径

以 Release 运行，使用 `Stopwatch` 墙钟时间。预览组合处理先预热至少 10 次且累计至少 1500ms，让 .NET 分层 JIT 完成优化，然后记录 5 次取中位数。组合处理包括全部调整、LUT、降噪、几何和直方图，尺寸是 1600px 预览经过旋转及中心 80% 裁切后的结果。单项调整耗时、首次解码、完整解码和编码只取一次观察值。实测发现进程启动初期只预热 300ms 仍可能得到约 100ms 的首图处理时间，随后降至约 15ms；稳态数字不涵盖这段启动成本。

JSON 记录 OS、.NET 版本、逻辑处理器数、CPU 标识、进程架构、可用内存预算、进程峰值工作集和 Magick.NET 版本。磁盘缓存没有被清空，其他进程负载没有锁定；因此这些数字适合发现瓶颈和本机回归，不是受控竞品基准，不应作为所有机器的性能承诺。

## 真实边界

- 只使用了 Nikon D4 和 Olympus E-M5MarkII 的三张样片；没有完成所有 NEF/ORF 机型、压缩方式、损坏形态的兼容认证。
- RAW 使用 LibRaw 实际显影；内嵌 JPEG 只用于快速显示。测试不把两者的颜色或像素完全一致当成要求。
- 显影后编辑使用 **8-bit sRGB RGBA**；没有验证 scene-linear 浮点工作流、相机 profile 的摄影色准、软打样、HDR 显示或 16-bit 编辑质量。
- 传统可分离双边降噪有数学行为验证，但没有与 DxO DeepPRIME、Adobe AI Denoise 或真实传感器 DGO 做画质对比。
- Native 解码操作不能在执行中立即停止；取消会在 native 阶段结束后丢弃结果。测试确认最终取消与资源恢复，不保证固定毫秒级取消延迟。
- 导出当前不复制原片 EXIF/IPTC/XMP；测试检查的是颜色声明和像素，不应据此宣称导出保留所有相机信息。
- PNG 使用同一底层编码器族回读；这是可靠的回环验证，但不是多个独立软件的互操作认证。JPEG 的平均误差阈值只能发现明显异常，不能替代视觉质量评估。
- 自动化测试没有覆盖屏幕截图比对、ICC 显示器配置、文件对话框、触控/高 DPI，也没有进行持续数小时的内存压力或上千张照片的批量测试。
